# Judge 9：Product Designer（产品设计师）评审报告

## 评审视角

我在一线产品团队做设计系统与产品体验。我打分时反复问的是四个问题：

1. **这是不是一个"系统"，还是一堆漂亮的局部？** token 有没有语义（而不是色板）、组件有没有逻辑（而不是布局灵感）、版式语法能不能扩展（而不是每页重新发明一次）。
2. **信息层级有没有一条清晰主线**：首屏（是谁/在想什么）→ 兴趣（在问什么）→ 证据（做过什么）→ 行动（找到这个人）。任何打断这条主线的选择都需要拿出充分理由。
3. **哪些 signature 是可维护的系统行为，哪些是孤立炫技？** 我的判断标准很残酷：6 个月后的维护者删不删得掉它、改数据时它会不会坏。附带明确禁用条件、降级路径、可整体开关的 signature 加分；依赖持续人工校准、无 lint 手段的"纪律"扣分。
4. **空状态是不是被当成系统问题设计**：内容少、内容多 10 倍、内容变化三种情形下版式是否都成立。

**一票否决区：`information_hierarchy`、`long_term_maintainability`。** 这两个维度我按"如果由我接手继续迭代"的标准从严评分：决策是否可延续、是否会被推翻。其余维度按常规标准。

一个总观察：这 8 份提案在"美学方向"上差异极大，但在"系统性"上分为三档——A/F/C 把约束写成了可执行规则（token 语义表、数据契约、派生编号），B/D 用隐喻产出了真语法但各自背着一笔自认的结构债，G/E/H 的系统性依附于其核心装置/材质而存在。另外有 3 个团队（C/E/H）都交了 Command Palette——判断高下的不是有没有，而是有没有写死禁用条件、索引来源、焦点归还与发现性策略。

## 逐方案评语

### Team A — Minimalism「Monograph 单行本」

- 优点：
  1. **§4.3 accent 使用位置全表（"除此之外的任何地方出现橙色都视为缺陷"）是全 8 案最可执行的 token 语义治理**——它把"克制"从品味问题变成了验收问题，lint 可查。橙色被绑定到"活着的东西"（当前章节、运行中实验、被投毒文档、焦点）这一个语义上，5 年内加任何新模块都能推导出"该不该用橙"。
  2. **§2.2 的可信度链条论证（Research→Work→Publications→Open Source 必须连续不间断）** 是全 8 案最清晰的信息层级主线陈述，且首屏→兴趣→证据→行动在单页长滚动里一气呵成；Lab 放中后段做"彩蛋"而不是抢黄金路径，是成熟的产品判断。
  3. **Dark 模式用 variable 轴把字重 500→470、字距 +0.004em 做光渗补偿**——全 8 案唯一把"暗底让字显胖"当作排版参数处理的方案，这是真懂排印的细节，且实现成本为零。
- 缺点/风险：
  1. **"衬线斜体全站 ≤10 处"与 accent 位置全表都需要持续人工执法**，文档只承诺"建立 lint 级自查"但没给自动化手段（如 stylelint 规则或组件层封装）。建议实现期把"双语气"收敛为一个 `<Emphasis>` 组件，把纪律固化进组件 API，否则 6 个月后必被稀释。
  2. **§6.1 只给了断点列数，section 骨架（sticky 左栏 + col 11–12 永远留白）在 768–1279 平板/小桌面如何退化没有定义**——左栏 sticky 在 8 列网格下占 3 列会把内容压到 62%，这是接手后第一个要自己补的决策。
  3. 纯文字构图在招聘者 10 秒扫读与 OG 分享场景吃亏（自查已承认）；骨架预案（静态生成排版式 OG 图）是对的，但应升级为 P0 交付项而非缓解项。
- 最值得被偷走的想法：**"accent 语义位置全表 + 违反即 bug"**——每个方案都该为自己的唯一强调色写出这张表。它同时解决了视觉纪律、暗色适配与长期维护三个问题。

### Team B — Editorial「Field & Retrieval 学刊」

- 优点：
  1. **三级规则线体系（hairline / strong rule / double rule 全站 ≤2 次）把"稀缺即权威"写成了可执行规则**，加上统一的 section opener 语法（strong rule→kicker→栏题→deck）与 4px 基线网格，Research/Work/Notes/Lab 共享同一套版式语法——这是真正的语法，不是主题。
  2. **§9 研究展示是全 8 案最强**：Part I–IV 特稿用"动机→当前理解（working notes）→下一步（开放问题）"叙事，研究问题做标题而非名词短语；marginalia 把 Notes 变成特稿的引用文献，站内互链形成"引文网络"——这是把研究者主页的灵魂模块当第一公民设计的。
  3. **WONK hover 是 signature 可维护性的典范**：一个变量轴、一个位置、280ms、自带移除开关（"评委若认为多余，一处开关即可移除，不影响体系"）——每个团队的 signature 都应该这么写规格。
- 缺点/风险：
  1. **首页把 Work 压缩为"In This Issue"底部的 3 行预览**，招聘者黄金路径（首屏→兴趣→证据→行动）在证据环节断流，只能靠 Contents 目录补救。作为产品决策我理解"研究者第一"的立场，但建议 Work 预览升格为独立 section 或至少 6 行。
  2. **4 族字体 ~260KB + 基线补差机制（图片破格后回贴）是持续维护税**——后者自查已给出降级路径（退化为仅保证 4 的倍数），建议直接把降级版定为 v1 验收标准。
  3. masthead 152px 的"复古"风险（自查承认）——对策"第一刀砍到 112px"应该在第一版就执行验证，而不是留作翻车后手術。
- 最值得被偷走的想法：**"空栏目在目录里保留一行——`— CALL FOR PAPERS`"**——空状态不是隐藏或道歉，而是让空栏目在导航结构里保持"栏目存在感"。这与 F 的"空 = 表格中一行"是全场两个最佳空态语法，可以合并成一条全站规则。

### Team C — Modern AI「精密仪器 Precision Instrument」

- 优点：
  1. **全 8 案最好的工程化产品契约**：§8 给出 `interface ProjectEntry` 数据契约、导航编号由内容派生自动重排、`outputs: []` 未来论文位"结构先于内容存在"、Relevance Lens 写死三条禁用条件（触屏 / reduced-motion / >12 条）。这是把"5 年内容生长"翻译成 schema 的做法，接手成本全场最低。
  2. **首屏 SYS 状态块全部真实计算（BUILD 注入、RECORDS 从 content 汇总、MODE 实时）**，`PUBS 0` 作为读数刻在面板上——诚实从内容策略升格成了产品特性；⌘K Palette 底部常驻 `METHOD: LEXICAL · LOCAL INDEX · N=41 · 0ms NETWORK` 是同一逻辑的延伸，是 3 个 Palette 里最有观点的一个。
  3. 硬约束自洽：mono ≤10%、刻度 ≤3 组/屏、琥珀同屏 ≤2 点——每条防滑条都对应一个具体的翻车形态，说明作者真的推演过执行。
- 缺点/风险：
  1. **Publications 排在 Research 与 Work 之间（§2.1 第 03 位），空 section 打断了兴趣→证据的主线**。"学术访客最早寻找"的理由不假，但更优解是把 `PUBS — 0 RECORDS` 收进 SYS 读数与 Research 区尾（它已经做了后者），把完整 section 后移。
  2. **首屏三联装置（标题 + SYS 块 + 关键词矩阵 + pipeline 图）信息密度是全 8 桨最高**：2 个脉冲点 + 1 个移动读数点 + hover 矩阵 + pipeline 注脚切换同时在场。纪律参数都在，但认知预算没有给——建议 v1 只保留 SYS 块 + 矩阵，pipeline 下移。
  3. ghost 槽位（opacity 8% 的假行位）与"诚实装置"原则轻微自相矛盾——全站都在教用户"读数皆真"，唯独空状态里放了假行。改用结构线或空槽位描边即可自洽。
- 最值得被偷走的想法：**"每个 signature 必须附带写死的禁用条件与降级路径"**（Relevance Lens：`hover:none` / reduced-motion / 条目 >12 全部禁用）——这是把炫技风险关进笼子的产品化写法，应成为所有交互规格的模板。

### Team D — Academic「抽印本 Offprint」

- 优点：
  1. **Question Ledger 是全 8 案最佳研究展示发明**：编号 + 追问 + OPEN / IN PROGRESS / RESTING 三态 + `upd. 2026-10`——它把"研究状态"本身做成了内容，且天然不需要编造 credential；Research Map 节点徽标只计未决问题数（`Q×n`），杜绝了伪造成果指标。
  2. **边注三段降级（≥1100px 浮动 → 平板行内 → 移动可折叠按钮，含完整 aria）是"边缘情况当系统问题设计"的教科书**——同一个信息装置在三种环境里各有被设计的形态，而不是删掉。
  3. Publications 的 ghost specimen 行是聪明的双层设计：既是优雅空态，又是**版式契约**（未来第一篇论文入库时"删除 specimen 换上真行，版式零改动"）。
- 缺点/风险：
  1. **手排 SVG 研究地图是明确的数据债**（自查承认"节点坐标是排出来的不是算出来的"）：领域从 6 涨到 10 就要重排。接手后我会在第一周就把节点坐标数据化（`content/research.ts` 已有 edges，补 layout 字段或降级为列表），否则这张最亮的图会最先烂掉。
  2. **状态诚实是运营负债**：`upd. 2026-10` 与 `RESTING` 三个月不更新就从"诚实的现场"变成"荒废的证据"（自查承认"对懒人是事故"）。5 年可持续性不能押在维护自觉上——建议加"超过 N 个月未更新的问题自动归入 RESTING"的派生规则，让系统自己诚实。
  3. 1000–1200px 中屏边注临界（自查承认）——"反复实测"不是方案，需要写死 fallback 断点（如 ≤1150px 直接切行内注）。
- 最值得被偷走的想法：**Question Ledger 的数据契约（`{id, text, area, status, followups[], updated}`）**——研究状态结构化后，地图、过滤器、反链、未来论文位全部自动生长，这是把"研究者在想什么"变成可维护数据的唯一路径。

### Team E — Creative Dev「BENCH / 工作台」

- 优点：
  1. **工件窗三态（Live / Schematic Session / 静态图）是全 8 案对"5 年后项目多了谁来维护 demo"最正面的回答**——任何项目至少能用最省力的 C 态保住版式完整（自查写明）。这是产品设计师才会写进方案的长期主义。
  2. **键盘体系 + 发现性三层 + focus 管理规范（§7.1–7.3）是全 8 案最完整的 UX 基础设施**：和弦表、非输入焦点保护、路由移焦到 h1、快捷键帮助浮层、情境层提示——把键盘当作一等导航而不是合规清单。
  3. **Research↔Lab 强制双向互链**（"读到的问题可以立刻上手，玩过的 demo 能跳回它服务的问题"）是信息架构层面的独有动线，把"能力证明"焊在"问题"上。
- 缺点/风险：
  1. **首屏装置 P-00 是全 8 案最重的单一维护面**：rAF 循环、sprite 图集、DPR 上限、降帧降级、双停机条件——预算表写得很好，但 6 个月后维护者最可能删的就是它。缺一个"终极降级预案"：装置退役时静态 SVG 快照常驻的版本应该现在就定义（renderStatic 已有，但没写"退役路径"）。
  2. **About 被折叠进 Hero 主张句 + Work 区侧栏 3 行**，身份模块是全 8 案最弱的——与"长期个人数字档案"的定位有张力；5 年后这个人有了履历，信息架构没有给 About 一个生长位。
  3. IBM Plex 单族让排版个性是 8 案里最弱的：记忆点几乎全押在装置与刻度母题上——装置若被降级，视觉身份跟着降级。
- 最值得被偷走的想法：**"工件窗三态"作为项目数据契约字段（`window: 'live'|'session'|'diagram'`）**——它承认维护成本会随时间上升，预先给每个项目留了"最低维护形态"。任何作品集方案都该偷这一条。

### Team F — Swiss「坐标系统 / Coordinate System」

- 优点：
  1. **"表 = 内容"的统一语法贯穿全部 8 个 section**（Work/OS/Notes/Timeline/Research R-INDEX/Lab 登记表全是索引表），加上编号数据驱动自动重排（"新增 section 不需要改导航代码"）与明确的组件清单（`<IndexTable>` `<SectionHeader>` `<GhostNumber>`）——这是全 8 案最干净、最容易交接的版式语法。
  2. **空状态 = 表格里的一行（`P— | Selected research will appear here. | —`）**：空态不是特例而是同一语法的一次取值，加上 FIG 待标注符号（对角交叉线 + `FIG. 02-A — PENDING`），空内容获得了与满内容完全一致的语言。
  3. 移动端"左脊线 + tick"把 12 列坐标纸塌缩成一根轴——体系感零丢失，是全 8 案最优雅的移动端系统保留方案。
- 缺点/风险：
  1. **冷是结构性风险（自查承认）**：`Dossier 留一行 CURRENTLY 活人字段"目前只是"对策"级别的细节。接手后我会把它升级为验收项，并要求 Notes 的写作声音承担更多温度——否则它就是一座漂亮的设计工作室档案馆，而不是一个人的主页。
  2. **outline 描边字（`-webkit-text-stroke`）跨浏览器渲染不一致**，且 `GENERATION` 一词以描边呈现损失了可读性——首屏最重要的单词恰恰是最难读的那个。建议实线 + 描边混排（只有一行描边）。
  3. **Dark 模式是全 8 案完成度最低的一套**：`#121212` 基底 + 提亮红基本是标准深色模板，"夜晚网格浮起"有想法但没有给出对应的 token 差异（hairline 提亮多少、红提亮多少只有数值没有推演）。
- 最值得被偷走的想法：**"空 = 表格中的一行 + 编号自动重排"**——把空状态与导航系统做成同一个数据派生问题。与 B 的 "CALL FOR PAPERS" 合并后就是全站空态语法的最终答案。

### Team G — Dark Premium「暗室与晨光 / The Dimmer Room」

- 优点：
  1. **§4.3"两套主题中行为不同的元素"对照表是全 8 案对"两套都被设计"最好的交付形式**：elevation 方向在 Light 反转（更白 = 更高）、发丝线方向反转（亮线压暗底 vs 暗线压亮底）、图片压亮 vs 直出——把"非反色"从口号变成了 11 行可验收的对照物。
  2. **Vitrine 展柜版式（7.5+3.5 舞台+铭牌、zigzag 交替、首条 21:9 全幅、无图时退化为"无图展台"）是最佳作品集展示力**，且空媒体兜底让它对 5 年后的内容形态免疫。
  3. 两个 signature 都带预算与自杀开关（First Light 1.6s / 会话一次 / compositor-only；"若实现质量不达，宁可砍掉扫光保留光晕"）——signature 的风险治理意识与 C 同级。
- 缺点/风险：
  1. **Research 区是 8 案最薄的智识展示**：关键词墙 + Q01/Q02/Q03 + 音响 spec 表，没有开放问题的追问层、没有状态语义（对比 D 的 Ledger、H 的 Query Log、B 的四部曲）。作为研究者主页，灵魂模块的密度不足。
  2. **材质系统的 QA 成本被低估**：e1/e2/e3 三级 surface + inner highlight + 2% 噪点 + 图片压亮 + Dark/Light 双图表序列——每个都是"差 5% 就显廉价"的细活。噪点纹理在低端设备上的合成成本也该进性能预算（目前没有）。
  3. Dark 默认立场（无偏好用户也默认 Dark）对招聘者白天扫读不友好——有 System 兜底，但"品牌记忆以 Dark 为准"意味着 OG 卡片、截图、分享场景全是暗的。
- 最值得被偷走的想法：**"两主题行为差异对照表"作为交付物**——以后所有双主题设计的验收都该先写这张表再写代码，它一次性杀死了"Light 是 Dark 的附庸"这个全场最常见的问题。

### Team H — Experimental「A Retrievable Self 可检索的人」

- 优点：
  1. **双通道原则 + §15 可用性守护清单是全场最好的"实验性与可用性的和解协议"**：每个实验性入口必有传统出口、`prefers-contrast: more` 关闭遮蔽、signal 状态永不依赖色相（配 ▲/文字）、reduced-motion 全量降级表——治理文档的完备度全 8 案第一。
  2. **证据链（问题→方法→产物→链接）是比卡片高一个代际的项目叙事语法**：横向空间 = 因果时间轴，问题站 ≤24ch 衬线口语短句给招聘者、方法站 mono 动词列表给研究者——同一条链服务两类访客。Query Log 的"为什么问 / 现在 / 什么算进展 / 关联"四行结构同样是诚实的-state 展示范例。
  3. **`--accent`（可信路径）与 `--signal`（攻击/不可信）的双色语义系统在教访客读研究**——配色服务于内容理解，这是"颜色即语义"的另一个正确示范。
- 缺点/风险：
  1. **§15.3 的 no-JS/SSR 承诺超出了锁定栈**：BRIEF 锁定 Vite 7 + React 19 SPA，"全部文本内容为服务端产出的真实 HTML"需要额外引入预渲染（vike 或构建期 prerender），文档没有交代这个依赖。要么补预渲染方案，要么把 no-JS 承诺降级为"noscript 提示 + 静态骨架"。
  2. **首屏遮蔽装置是全 8 案最大的首因风险**：招聘者 0.5 秒一瞥里四行摘要是 blur(5px)+0.35——"故意的"和"渲染坏了"在视觉上不可区分。防御做得很足（名称可读、DOM 全文、1.5s 首揭示承诺、resolved 记忆），但 product 判断依然是：把"未检索"隐喻押在首屏第一印象上，赌注大于收益。建议第一行默认已揭示。
  3. 活面最大：装置 + palette + 三玩具 + 双模导航，隐喻红线（仅 4 触点）需要 lint 级执法——而这份文档没有像 A/C 那样给出执法机制。
- 最值得被偷走的想法：**"双通道原则"作为全站验收标准**——每个实验特性必须在同一天设计传统出口与降级形态。这条写进任何方案的实现验收清单，能直接消灭一半的炫技事故。

## 排名与理由

**Top 3：A（Monograph 单行本）> C（精密仪器）> B（Field & Retrieval 学刊）**

- **第一 · A**：在我的两个否决维度上都是全场最高——`information_hierarchy` 9（可信度链条连续性被写成设计公理，首屏→兴趣→证据→行动一条线不断）与 `long_term_maintainability` 9.5（无卡片、无图标、行即语法、Notes>20 拆分规则、空 section 构建期跳过、accent 位置全表、动效预算表）。它的 signature（落墨 Settle + caret）是全 8 案最便宜的可维护系统行为；它的空状态（不渲染 + 一句承诺行 + LAST UPDATED）最干净。**接手测试满分：我几乎会延续它的每一个决策，需要补的只有平板骨架退化与"双语气"组件化两处。**
- **第二 · C**：输给 A 的地方在 `information_hierarchy` 7.5——空 Publications 卡在兴趣与证据之间，且首屏三联装置的认知密度到了上限。但它的产品工程素养是全场第一：数据契约、派生编号、`outputs: []` 未来论文位、signature 禁用条件写死、诚实读数成为产品特性。`long_term_maintainability` 9 与 A 并列第一梯队。**接手测试：我保留全部契约与治理规则，只做两处结构修订（Publications 后移、首屏减一联）。**
- **第三 · B**：`research_presentation` 9（四部曲特稿 + 引文网络）与 `typography` 9（四级字体 + 基线网格 + 稀缺性规则）都是全场最高档，且它的隐喻纪律（只落 4 个结构位、编号由真实日期推导）让语法可以随内容生长。落选前二的原因：`information_hierarchy` 7.5（Work 在首页只是 3 行预览，招聘者黄金路径断流）与 4 族字体的维护税。**接手测试：我会保留 opener 语法与规则线体系，把 masthead 降到 112px、字体砍到 3 族——这些修订文档自己都预授权了，说明决策内核是稳的。**
- 未进 Top 3 但值得记录：
  - **F**（第 4，差半步）：版式语法的纯净度与可交接性仅次于 A，"空 = 表格中一行"是最佳空态语法之一。但它要补的两课——冷（结构性的）与 Dark 模式（全 8 案最弱）——恰好一个动它的身份、一个要重做一整套 token，我把它排第 4。
  - **D**（第 5）：Question Ledger 是我最想直接搬走的东西，但手排地图数据债 + 状态诚实依赖维护自觉，是 `long_term_maintainability` 上的两笔真实负债（作者自己都承认了）。
  - **G**（第 6）：双主题对照表与 Vitrine 是两件最佳单项，但灵魂模块（Research）最薄。
  - **E**（第 7）：UX 基础设施最好，但首屏装置是最重的单一维护面，且排版个性最弱——signature 与视觉身份同生共死是结构性风险。
  - **H**（第 8）：原创性全场第一、治理文档最好，但 no-JS 承诺超出锁定栈 + 首屏遮蔽是我作为产品决策者不会签字的两个点。

## 给第二轮的交接备忘（全场可合并的系统级共识）

1. **accent 语义位置全表（A）+ signature 禁用条件（C）+ 双通道原则（H）** 应合并为第二轮的统一治理模板。
2. **空状态语法**：F 的"空 = 表格中一行" + B 的"空栏目保留目录存在感" + D 的"ghost specimen 版式契约"三者可合成一条全站规则：空态与满态共享同一语法、空模块有存在感、空态即未来版式的契约。
3. **双主题交付物**：G 的 §4.3 行为差异对照表应成为所有方案 Dark/Lark 验收的前置文档。
4. **研究状态结构化**：D 的 Question Ledger 契约 + H 的 Query Log 四行结构 + C 的 `outputs: []` 是同一件事的三段拼图——研究状态数据化后，地图/过滤器/论文位全部自动生长。
